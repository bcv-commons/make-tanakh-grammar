# Rules-engine lab, first day: rung 1 (Greek NT → English) and rung 1b (Hebrew → English), 2026-10-26

Design: `internal-docs/rules-engine-lab.md`. Code: `scratch/rules/` (data/, engine/, rules/, results/). No LLM generates any
text; two linguist-agent rounds wrote rules (about 0.3M tokens in all). All figures below are against the BSB and its own
alignment; the held-out test chapters (Mark 5, 10, 15; Genesis 22, 37, 44) were read once, at the end (`results/final_test.json`).

(Paths as of that day. Since 2026-10-29 the code is in this repo's `lab/rules/`, the design in `docs/rules-engine-lab.md`, the
results in `$MAKE_TANAKH_PRIVATE/rules/`.)

## 3. What we learned

1. **Order is learnable as rules, from little data, in both directions.** The order rules raise τ by 0.05 (NT) and 0.045 (Tanakh)
   on unseen chapters; on dev they already worked when trained on Mark alone (0.785 → 0.865 from 404 verses). The rule is plain
   data: "MACULA rule V-S-ADV with these children → English order S-V-ADV". That is TBTA's constituent movement, found by counting.
2. **The contrasts are in the data and the method finds them.** In the present indicative, +s appears only in the 3rd singular
   (30-45%; the rest are irregulars and historic presents rendered as past), never in the 2nd (≤ 2%); a subject pronoun
   ("he", 122 times) appears only when the clause has no explicit subject. Nothing told the scripts English has these.
3. **Function words depend on context, and cell rules shared by all lemmas carry them** (E5: +1.0 to +1.5 chrF, function-word
   precision +0.07 on the honest pool, significant on both rungs).
4. **Consistency and reference scores pull apart.** E6, the TBTA-style split (choose the word, then inflect it), is the only
   stage that behaves like a rule engine under the swap tests: the same English verb in 100% of swaps, no stray +s, the pronoun
   added in 82-89% (E1: 50% same verb, 8% pronoun). But the reference rewards memory of exact renderings (E7, E5), and E6 loses
   2-4 chrF where memory is rich (the whole NT with parallels, the Tanakh). Both kinds of measure are needed; neither alone says
   how good the engine is.
5. **Synoptic parallels inflate the lexicon.** On Mark, word choice is 0.71 with the gospels in training and 0.55 without. For
   rules, the honest pool is the one without the parallels.
6. **The linguist agent's value was diagnosis, not rules.** Round 1 kept 21 rules (+0.38 chrF on dev) and found that their main
   cause was an engine gap (lemmas rendered with function words only); once the engine handled that, 17 of 21 were redundant.
   Round 2 kept 19 small rules (+0.18 [0.00, 0.40] on test) and reported the current context fields used up. Both rounds' ranked
   lists of missing capabilities are the most useful output (`rules/en_bsb_r1_notes.md`, `en_bsb_r2_notes.md`).
7. **The same engine runs on Hebrew** with a thin adapter (the word as the unit, its prefixes as features); its order and cell
   rules gain as on the Greek. E6's function words are weak on Hebrew (recall 0.34) because the word's own prefixes are not yet
   a part of E6's "pre" (they are in E5's cells).

## 4. What remains, in the order I would do it

1. **Participant tracking**, the capability both linguist rounds ranked first (subject continuity: ~120 dev differences;
   pronoun referents: ~110). `scripts/participants.py` builds participant ids for the NT from `orig/grc.sqlite`; the engine's
   context would get "same subject as the previous clause" and "this pronoun refers to X". This is the first of TBTA's record
   features we need.
2. **The governing verb and the object's case** for conjunctions (~157) and prepositions (~83); definiteness / proper names for
   the article (~75). All are in MACULA's tree; they need context fields, not new data.
3. **E6's pre for Hebrew prefixes** (the word's own conjunction, preposition, article), then rerun rung 1b.
4. **A consistency-and-reference combination:** E7's memory only where it is consistent with E6 (same English verb, agreeing
   function words), so the engine keeps E6's behaviour under swaps and E7's accuracy.
5. **Linguist round 3** after 1-2, with the new fields.
6. **Rung 1c (KJV)** when lexeme-aligner delivers the full alignment (request sent as note 12): the same transfer rules, a second
   spellout table (thou / ye, -est / -eth), measured on the same Greek.
7. The swap tests for the other features (number, tense, voice, negation) and the elicitation sample (§4a kind 4).

## 5. Notes

- The lab rebuilds the BSB alignment from the tables; `orig/grc.sqlite`'s `bsb` table (lexeme-aligner's layer) is not used.
- The engine's code was changed twice after agent rounds (r1: function-word-only renderings, `first`, `next_class`; r2: the
  corpus check on regular forms, `prev_class`, `prev_lemma`); copies of each version are kept (`engine/*.r1.py`, `*.r2.py`).
- The agents wrote rules from the data, but they know English: on this rung their rules may draw on that knowledge. The rule
  test (gain on training, no loss on dev) is what decides, and the test chapters were never seen by them.
- Nothing here is committed; `scratch/` and `internal-docs/` are git-ignored.
