# Morphosyntax encoding standards (UD, UniMorph, Leipzig Glossing Rules, GOLD, OLiA, ISOcat/DatCatInfo, CLDF) and their fit for a universal per-clause Bible-drafting specification

Research notes, 2026-10-22. Versions checked: UD v2.18 (released 2026-05-15), UniMorph 4.0 (2022; schema document still Sylak-Glassman 2016 "Draft, Version 2"), Leipzig Glossing Rules (Feb 2008 revision, last change 2015-05-31), GOLD 2010, OLiA (GitHub, 2026), CLDF 1.3, DatCatInfo (successor of ISOcat). All extracted texts and the downloaded PDFs are in the session scratchpad (`pdf/*.txt`), not in the repo.

## KQ0a. Inventory: Universal Dependencies v2 (relations, features, values, formats)

### Takeaway
UD v2 is the only one of the standards that covers *both* clause relations and morphological features, in a fixed, documented inventory (37 relations; 27 universal feature names with ~200 values) plus an open, documented language-specific extension mechanism (relation subtypes `base:sub`, extra features, layered features `Name[layer]`). Its data format (CoNLL-U) and the extension format (CoNLL-U Plus) are plain tab-separated text that any Python script reads with `str.split`.

### Cited Findings

**Releases and size**
- UD home page: "Release 2.18" dated May 15, 2026; the page says "over 200 treebanks in over 150 languages" and "over 600 contributors" (the wording looks stale, see next item) — [UD home](https://universaldependencies.org/)
- The LINDAT record for UD 2.18 is dated 2026-05-15 and lists 2,337,062 sentences, 37,424,698 tokens, 38,181,322 words (archive ud-treebanks-v2.18.tgz, ~652 MB). The previous release (v2.17, 2025-11-15) is listed on the download page with 339 treebanks in 186 languages — [LINDAT UD 2.18](https://lindat.mff.cuni.cz/repository/items/7fbbbd99-ae2d-4b91-8318-d996dbe34cbc); [UD download page](https://universaldependencies.org/download.html)
- The UD GitHub organisation holds 500 repositories (API listing, 2026-10-22) — [github.com/UniversalDependencies](https://github.com/UniversalDependencies)

**The 37 universal relations** (one-line definitions as on the index page) — [UD u/dep index](https://universaldependencies.org/u/dep/index.html)
- Core arguments: `nsubj` nominal subject, `obj` direct object, `iobj` indirect object, `csubj` clausal subject, `ccomp` clausal complement, `xcomp` open clausal complement.
- Non-core dependents: `obl` oblique nominal, `vocative`, `expl` expletive, `dislocated`, `advcl` adverbial clause modifier, `advmod`, `discourse`, `aux`, `cop`, `mark`.
- Nominal dependents: `nmod`, `appos`, `nummod`, `acl` clausal modifier of a noun, `amod`, `det`, `clf` classifier, `case`.
- Coordination: `conj`, `cc`. MWE/flat: `fixed`, `flat`, `compound`, `list`. Loose/special/other: `parataxis`, `orphan`, `goeswith`, `reparandum`, `punct`, `root`, `dep`.
- Subtypes: "A subtyped relation always starts with the basic type, followed by a colon and the subtype string"; "subtypes are language-specific and optional". The index names these semi-mandatory subtypes: `acl:relcl`, `advcl:relcl`, `aux:pass`, `csubj:outer`, `csubj:pass`, `expl:impers`, `expl:pass`, `expl:pv`, `nsubj:outer`, `nsubj:pass`, `obl:agent`; and as an "arbitrary selection" of others: `advmod:emph`, `advmod:lmod`, `cc:preconj`, `compound:lvc`, `compound:prt`, `compound:redup`, `compound:svc`, `det:numgov`, `det:nummod`, `det:poss`, `flat:foreign`, `flat:name`, `nmod:poss`, `nmod:tmod`, `nummod:gov`, `obl:arg`, `obl:lmod`, `obl:tmod` — [UD u/dep index](https://universaldependencies.org/u/dep/index.html)
- Adverbial-clause subtypes exist in individual treebanks but there is no universal list: e.g. `advcl:cond` (Uyghur-UDT 20 instances; Sanskrit-Vedic 686; Abkhaz-AbNC 40), `advcl:purp` (Egyptian-PC 456; Abkhaz; Bokota/Ika ChibErgIS), `advcl:tcl` listed as sibling subtype in Sanskrit-Vedic and Egyptian-PC — [ab_abnc advcl:purp](https://universaldependencies.org/treebanks/ab_abnc/ab_abnc-dep-advcl-purp.html); [ug_udt advcl:cond](https://universaldependencies.org/treebanks/ug_udt/ug_udt-dep-advcl-cond.html); [sa_vedic advcl:cond](https://universaldependencies.org/treebanks/sa_vedic/sa_vedic-dep-advcl-cond.html); [egy_pc advcl:purp](https://universaldependencies.org/treebanks/egy_pc/egy_pc-dep-advcl-purp.html)
- The cross-treebank subtype index (`ext-dep-index.html`) and the cross-treebank feature index (`ext-feat-index.html`) both returned HTTP 404 on 2026-10-22 (curl check); only per-treebank statistics pages remain.

**Clause-level conventions (complex syntax)** — [UD complex syntax overview](https://universaldependencies.org/u/overview/complex-syntax.html)
- `ccomp` vs `xcomp`: `xcomp` "marks obligatory control, where the subject must match a higher argument"; `ccomp` "allows the subject to be anaphorically independent"; object control uses an object-with-infinitive analysis (the controlled subject is `obj`/`iobj`).
- `advcl` covers temporal, conditional, purpose etc. clauses and optional depictives; obligatory predicatives and resultatives are `xcomp`.
- `acl` for adnominal clauses; relative clauses `acl:relcl`; content clauses after nouns like *fact* plain `acl`.
- Coordination: `conj` with "the first conjunct as the parent (or 'technical head')"; `cc`/`punct` attach to the following conjunct; asyndetic coordination = `conj` without `cc`.
- Ellipsis: promote `aux`/`cop`; otherwise `orphan` for stranded siblings.
- Multiple subjects of a clausal predicate in copula constructions: `nsubj:outer`/`csubj:outer`.
- Direct speech: "Direct quotations are attached as ccomp, 'even with inverted order'" (ccomp(asked, know)); "Quoted content is considered to be ccomp even if it is a sentence fragment"; when the speech verb interrupts the quote, `parataxis` is used and the speech verb "attaches to the root of the reported speech" — [UD ccomp](https://universaldependencies.org/u/dep/ccomp.html); [UD parataxis](https://universaldependencies.org/u/dep/parataxis.html)
- `parataxis` other uses: side-by-side run-on sentences, sub-sentence units, clauses linked by *so/then/therefore/however*, bylines, interjected clauses, tag questions; "a discourse-like equivalent of coordination" — [UD parataxis](https://universaldependencies.org/u/dep/parataxis.html)
- `dislocated`: "fronted or postposed elements that do not fulfill the usual core grammatical relations"; fronted element attaches to the head of its clause; postposed ones attach to the governor of the dependent they double; a topic-marked noun that is the subject is `nsubj`, not `dislocated` — [UD dislocated](https://universaldependencies.org/u/dep/dislocated.html)
- `discourse`: interjections, feedback markers, fillers, "particles that cannot be classified as adverbs, adpositions, etc." (question particles, vocative particles), list enumerators, emoticons; adverbs (*actually*) and PPs (*in other words*) excluded — [UD discourse](https://universaldependencies.org/u/dep/discourse.html)
- `vocative`: "used to mark a dialogue participant addressed in a text", attached to the main predicate (vocative(take, Guys)) — [UD vocative](https://universaldependencies.org/u/dep/vocative.html)

**Universal features and their exact values** (compiled from the index, the per-feature pages and the all-features page) — [u/feat index](https://universaldependencies.org/u/feat/index.html); [u/feat/all](https://universaldependencies.org/u/feat/all.html)
- Lexical: `PronType` = Art, Dem, Emp, Exc, Ind, Int, Neg, Prs, Rcp, Rel, Tot · `NumType` = Card, Dist, Frac, Mult, Ord, Range, Sets · `Poss` = Yes · `Reflex` = Yes · `Foreign` = Yes · `Abbr` = Yes · `Typo` = Yes · `ExtPos` = UPOS values (ADJ, ADP, ADV, AUX, CCONJ, DET, INTJ, PRON, PROPN, SCONJ seen).
- Nominal: `Gender` = Masc, Fem, Neut, Com · `Animacy` = Anim, Hum, Inan, Nhum · `NounClass` = Bantu1…Bantu23, Wol1…Wol12 · `Number` = Sing, Plur, Dual, Tri, Pauc, Grpa, Grpl, Inv, Count, Ptan, Coll · `Case` (37) = Nom, Acc, Abs, Erg, Abe, Ben, Cau, Cmp, Cns, Com, Dat, Dis, Equ, Gen, Ins, Par, Tem, Tra, Voc, Abl, Add, Ade, All, Del, Ela, Ess, Ill, Ine, Lat, Loc, Per, Sbe, Sbl, Spl, Sub, Sup, Ter · `Definite` = Com, Cons, Def, Ind, Spec · `Deixis` = Prox, Med, Remt, Nvis, Abv, Bel, Even · `DeixisRef` = 1, 2 · `Degree` = Pos, Cmp, Sup, Equ, Abs, Dim, Aug.
- Verbal: `VerbForm` = Fin, Inf, Sup, Part, Conv, Gdv, Ger, Vnoun — [VerbForm](https://universaldependencies.org/u/feat/VerbForm.html) · `Mood` = Ind, Imp, Cnd, Pot, Sub, Jus, Prp, Qot, Opt, Des, Nec, Irr, Adm, Int — [Mood](https://universaldependencies.org/u/feat/Mood.html) · `Tense` = Past, Pres, Fut, Imp, Pqp ("the term [aorist] is better avoided in UD annotation"; Bulgarian aorist is `Past`) — [Tense](https://universaldependencies.org/u/feat/Tense.html) · `Aspect` = Hab, Imp, Iter, Perf, Prog, Prosp (Perf glossed "perfect", "this aspect does not work well with the present tense"; Czech perfective verbs are also `Perf`) — [Aspect](https://universaldependencies.org/u/feat/Aspect.html) · `Voice` = Act, Antip, Bfoc, Cau, Dir, Inv, Lfoc, Mid, Pass, Rcp ("Causative forms of verbs are classified as a voice category"; applicatives are not mentioned) — [Voice](https://universaldependencies.org/u/feat/Voice.html) · `Evident` = Fh, Nfh · `Polarity` = Pos, Neg · `Person` = 0, 1, 2, 3, 4 · `Polite` = Infm, Form, Elev, Humb · `Clusivity` = In, Ex.
- Documented non-universal features on the all-features page: `NumForm` = Word, Digit, Combi, Roman; `Style` = Arch, Coll, Expr, Form, Rare, Slng, Vrnc, Vulg; `PartType` = Emp, Inf, Int, Mod, Neg, Vbp; `PrepCase`; `PunctSide`; `PunctType`; `Subcat` = Ditr, Indir, Intr, Tran; `VerbType` = Aux, Cop, Light, Mod, Quasi; layered `Number[abs|erg|dat|obj|subj|psed|psor]`, `Person[abs|erg|dat|obj|psor|subj]`, `Polite[abs|erg|dat]` — [u/feat/all](https://universaldependencies.org/u/feat/all.html)
- `NounClass` guidance: noun class "is largely a lexical property of nouns, and other parts of speech inflect for it to show agreement"; "No language family uses both the features [Gender and NounClass]"; in Bantu noun class also encodes number, so nouns get `Number` as well and "The lemma of the noun should be its singular form"; Wolof class is "morphologically unmarked on nouns" but determiners agree (ki, gi, ji) — [NounClass](https://universaldependencies.org/u/feat/NounClass.html)
- Morphology principles: "Every feature has the form Name=Value"; lexical vs inflectional features; language-specific features "should be described in the language-specific documentation"; identifiers use English letters/digits, first letter uppercase, and value codes are not unique across features ("Sup could denote the superessive case, superlative degree of comparison or supine"); layered features: "If a feature is (can be) layered in a language, the name of the feature must indicate the layer", layer identifier in square brackets, e.g. `Gender=Masc|Gender[psor]=Fem`, and "The layers, their meaning and their identifiers must be defined in a language-specific extension" — [UD morphology overview](https://universaldependencies.org/u/overview/morphology.html)

**CoNLL-U and CoNLL-U Plus** — [UD format](https://universaldependencies.org/format.html); [CoNLL-U Plus](https://universaldependencies.org/ext-format.html)
- 10 tab-separated columns: ID, FORM, LEMMA, UPOS, XPOS, FEATS, HEAD, DEPREL, DEPS, MISC; `_` for unspecified; only FORM, LEMMA, MISC may contain spaces.
- FEATS: `Name=Value` pairs joined by `|`, attributes sorted alphabetically (case-insensitive), multiple values comma-separated and sorted (`Case=Acc,Dat`); feature names must match `[A-Z][A-Za-z0-9]*(\[[a-z0-9]+\])?`, values `[A-Z0-9][A-Za-z0-9]*`; DEPREL must match `[a-z]+(:[a-z]+)?`; DEPS = `head:relation` pairs sorted by head, may use extended relation strings.
- Multiword tokens (`1-2` ranges, surface FORM only), empty nodes (`i.1`), compulsory `# sent_id` and `# text` comments; optional `translit`, `text_en`, `newdoc`, `newpar`; MISC conventions `SpaceAfter=No`, `Translit`, `Gloss`, `MSeg`, `MGloss`.
- CoNLL-U Plus (`.conllup`): first line `# global.columns = ID FORM ... ` names the columns; any subset/order of the ten standard columns plus project-specific columns with a namespace prefix (`PARSEME:MWE`); `_` = underspecified, `*` recommended for "empty" where it must differ from "unknown"; optional `source_sent_id` cross-reference to a UD release; "Planned extensions include Unimorph-style morphology and named-entity annotation."

### Inferences
- UD's `Name=Value|…` FEATS string and `base:subtype` DEPREL are the de-facto machine-readable standard; the value codes are deliberately short (2–5 chars) and the regex constraints make a validator trivial.
- The layered-feature convention (`NounClass[obj]`, `Person[subj]`) is UD's sanctioned way to put concord information on a verb token, which is exactly what a Bantu verb template needs; Ruuli-RDT and Yupik-SLI already use it (see KQ3).
- UD does not define `advcl` subtypes universally; a project needs its own documented set (e.g. `advcl:cond`, `advcl:purp`, `advcl:tcl` are attested in several treebanks, so reusing those names costs nothing).

### Gaps
- The cross-treebank indexes of relation subtypes and of language-specific features are offline (404), so I could not produce the complete list of attested `advcl:*`/`acl:*`/`obl:*` subtypes across all 2.18 treebanks.
- Exact 2.18 treebank/language counts were not found on the pages fetched (only 2.17: 339/186).

## KQ0b. Inventory: UniMorph (schema dimensions and labels, versions, coverage, licence)

### Takeaway
UniMorph gives the richest *morphological* label inventory (23–25 dimensions, ~290 labels incl. Valency APPL/CAUS, Switch-Reference SS/DS, Person INCL/EXCL, 11 evidentials, Gender BANTU1–23), but no clause relations; since 4.0 (2022) it has a hierarchical bracket syntax for polypersonal agreement and case stacking. Data are CC BY-SA 3.0 (most languages); the schema is still documented by a 2016 draft PDF, and the website's "schema" page says "Coming soon".

- Example data repo: `unimorph/swc` (Swahili verbs from Wiktionary + "102 Swahili Verbs"), annotator Jennifer White, "License: Creative Commons Attribution-ShareAlike 3.0 Unported (CC BY-SA 3.0)" — [github.com/unimorph/swc](https://github.com/unimorph/swc)
- Data format (from the UD-compatibility README example): a UniMorph record is lemma, form and a feature bundle such as `PRS;V;FIN;3;IND;SG` — [ud-compatibility README](https://github.com/unimorph/ud-compatibility)

### Inferences
- The 182 (paper) vs 169 (site) language counts disagree; the site listing is probably the maintained one.
- UniMorph's label set is a superset of what the Kuni/Zinza profiles need for *morphology* (APPL, CAUS, SS/DS, INCL/EXCL, HOD/RMT tenses, BANTU1-23), and its labels coincide with Leipzig abbreviations in most cases (see KQ1), so a project feature vocabulary could be "UniMorph labels in UD slots".
- The hierarchical 4.0 syntax `NOM(3,SG,BANTU1);ACC(BANTU7)` is the UniMorph equivalent of UD's `Person[subj]/NounClass[obj]` layers; both are one-line parsable, UD's with `split`, UniMorph's with a 10-line recursive parser.

### Gaps
- No licence statement was found for the schema document itself or for the `unimorph` PyPI package (GitHub shows no licence; PyPI licence field empty).
- The 4.0 hierarchical schema is documented only in the paper; the site's schema page is a placeholder, so which released language files actually use the bracket syntax was not verified.

## KQ0c. Inventory: Leipzig Glossing Rules (2008/2015) and standard abbreviations

### Takeaway
The Leipzig Glossing Rules are ten syntax rules for interlinear glosses plus an appendix of 85 standard category abbreviations; they define the morpheme-level notation (hyphen, `=` clitic, `.` fused categories, `:`/`;`/`_` optional variants, `\` for non-concatenative marking such as tone, `>` agent>patient, `[ ]`, `( )`, `< >` infix, `~` reduplication). The document carries no licence or copyright statement; its last change is dated 2015-05-31.

### Cited Findings
- Authorship and status: "developed jointly by the Department of Linguistics of the Max Planck Institute for Evolutionary Anthropology (Bernard Comrie, Martin Haspelmath) and by the Department of Linguistics of the University of Leipzig (Balthasar Bickel)"; "(revised version of February 2008)"; "Leipzig, last change: May 31, 2015. Further updates will be managed by the Committee of Editors of Linguistics Journals." — [Glossing-Rules.pdf](https://www.eva.mpg.de/lingua/pdf/Glossing-Rules.pdf)
- The web page states no licence or reuse terms; only a PDF is offered — [eva.mpg.de glossing-rules page](https://www.eva.mpg.de/lingua/resources/glossing-rules.php)
- Scope statement: "The main purpose that is assumed here is the presentation of an example in a research paper or book. When an entire corpus is tagged, somewhat different considerations may apply … the rules here only allow for information about morphemes" — [PDF](https://www.eva.mpg.de/lingua/pdf/Glossing-Rules.pdf)
- The ten rules (PDF): 1 word-by-word alignment; 2 morpheme-by-morpheme correspondence with hyphens, clitics with `=` (2A: hyphen+space for bound elements that are separate prosodic words); 3 category labels in upper case/small caps, deviations allowed (CPL for COMPL, PF for PRF); 4 one-to-many correspondences joined by periods (`GEN.PL`), 4A `_` for unsegmentable multi-word metalanguage (`come_out`), 4B `;` for unsegmentable but distinct categories (`GEN;PL`), 4C `:` for segmentable but unsegmented (`that:DAT;SG`), 4D `\` for morphophonological change "(ablaut, mutation, tone alternation, etc.)" e.g. Kinyarwanda *mú-kòrà* `SBJV\1PL-work`, 4E `>` for agent>patient portmanteau (`2DU>3SG-FUT-poke`); 5 person and number not separated (`1PL`, not `1.PL`), 5A optional lower-case short forms (`1s`, `3ns`); 6 non-overt elements in square brackets or `-Ø`; 7 inherent categories in parentheses (`tree(G4) G4-bend-PRET`); 8 bipartite elements repeated or `STEM`/`CIRC`; 9 infixes in angle brackets (`b<um>ili` `<ACTFOC>buy`); 10 reduplication with `~` (`bi~bili` `IPFV~buy`).
- Appendix "List of Standard Abbreviations" (verbatim, 85 entries): 1 first person; 2 second person; 3 third person; A agent-like argument of canonical transitive verb; ABL ablative; ABS absolutive; ACC accusative; ADJ adjective; ADV adverb(ial); AGR agreement; ALL allative; ANTIP antipassive; APPL applicative; ART article; AUX auxiliary; BEN benefactive; CAUS causative; CLF classifier; COM comitative; COMP complementizer; COMPL completive; COND conditional; COP copula; CVB converb; DAT dative; DECL declarative; DEF definite; DEM demonstrative; DET determiner; DIST distal; DISTR distributive; DU dual; DUR durative; ERG ergative; EXCL exclusive; F feminine; FOC focus; FUT future; GEN genitive; IMP imperative; INCL inclusive; IND indicative; INDF indefinite; INF infinitive; INS instrumental; INTR intransitive; IPFV imperfective; IRR irrealis; LOC locative; M masculine; N neuter; N- non- (e.g. NSG nonsingular, NPST nonpast); NEG negation, negative; NMLZ nominalizer/nominalization; NOM nominative; OBJ object; OBL oblique; P patient-like argument of canonical transitive verb; PASS passive; PFV perfective; PL plural; POSS possessive; PRED predicative; PRF perfect; PRS present; PROG progressive; PROH prohibitive; PROX proximal/proximate; PST past; PTCP participle; PURP purposive; Q question particle/marker; QUOT quotative; RECP reciprocal; REFL reflexive; REL relative; RES resultative; S single argument of canonical intransitive verb; SBJ subject; SBJV subjunctive; SG singular; TOP topic; TR transitive; VOC vocative — [PDF](https://www.eva.mpg.de/lingua/pdf/Glossing-Rules.pdf)

### Inferences
- The Leipzig list has no abbreviations for noun classes (only CLF and the Rule-7 `(G4)` device), switch-reference (SS/DS are community usage, not in the list), evidentials (only QUOT), politeness, jussive (IMP covers it; PROH is separate), aorist or binyan; a project must add these and document them, which Rule 3 explicitly allows.
- Rule 4D's backslash is the only standard notation for tone-marked grammar in any of the standards reviewed (UD and UniMorph have no tone device).

### Gaps
- No licence: reuse of the abbreviation list is universal practice but not formally granted; I found no statement on the PDF or page.

## KQ0d. Inventory: GOLD, OLiA, ISOcat/DatCatInfo, CLDF

### Takeaway
GOLD (2010, OWL, 502 classes) and OLiA (reference model + annotation models; data CC BY 3.0) are ontologies that *name* concepts and link tagsets, not annotation formats; ISOcat is discontinued and DatCatInfo is "all rights reserved". CLDF (1.3, Apache-2.0) is the practical tabular format: CSV + JSON metadata, with an ExampleTable for Leipzig-style IGT (Analyzed_Word/Gloss, LGR_Conformance) and a ParallelText module whose worked example is the Parallel Bible Corpus keyed by verse ids like `40001001`.

### Cited Findings
- GOLD: "formal account of the basic categories and relations used in describing human language"; versions 2010, 2009, 2008 as OWL files (e.g. https://static.vocabs.clariah.nl/cache/gold/2010.owl); no licence stated on the site — [linguistics-ontology.org](http://linguistics-ontology.org/); the 2010 OWL header has `owl:versionInfo 2010`, creators Scott Farrar and D. Terence Langendoen, contributors incl. Corbett, Kibort, Lewis, Moran, Simons, and no licence/rights element; the file contains 502 `owl:Class` declarations (grep count) — [gold/2010.owl](https://static.vocabs.clariah.nl/cache/gold/2010.owl)
- OLiA (Ontologies of Linguistic Annotation): "an OWL/DL taxonomy of data categories" (Reference Model) + Annotation Models + Linking Models; the Reference Model "is linked to … GOLD (http://linguistics-ontology.org/) and ISOcat (http://www.isocat.org)"; licence callout "code: Apache v.2", "data: CC-BY 3.0"; "The SourceForge edition (until 2019) used CC-BY-SA 3.0" — [OLiA Readme](https://acoli-repo.github.io/olia/owl/Readme.md); [github.com/acoli-repo/olia](https://github.com/acoli-repo/olia)
- The 2013 OLiA journal paper reports that "GOLD and ISOcat should be available under an open license, but can currently not be redistributed because of an uncertain licensing situation (no explicit license information)" — [Semantic Web Journal, OLiA](https://www.semantic-web-journal.net/content/olia-ontologies-linguistic-annotation)
- ISOcat/DatCatInfo: DatCatInfo "replaces the former ISOcat", "developed according to the ISO 12620 series of standards", run by the volunteer DatCat Council under LTAC Global/TerminOrgs, hosted in TermWeb by Interverbum Tech; "work in progress"; footer "© Copyright DatCatInfo. All rights reserved."; no licence, no download/API mentioned — [datcatinfo.net](https://datcatinfo.net/); ISOcat is "now discontinued" (search summary) — [sourceforge ISOcat](https://sourceforge.net/p/isocat/)
- ISO 12620:2019 "Management of terminology resources — Data category specifications", Edition 3, 2019-05; the ISO catalogue page could not be fetched (HTTP 403); a search summary says ISO marks it as withdrawn (unverified) — [ISO 12620:2019](https://www.iso.org/standard/69550.html)
- CLDF: "CLDF 1.3 is the current release"; builds on W3C CSVW (JSON-LD metadata + UTF-8 CSV); ontology at `v1.0/terms.rdf`; grew out of clld/Glottobank — [cldf.clld.org](https://cldf.clld.org/); spec repository licence Apache-2.0; modules Wordlist, StructureDataset, Dictionary, ParallelText, TextCorpus, Generic; "many properties are similar to those in GOLD … CLDF includes its own terms to avoid ambiguity and references the related GOLD properties" — [github.com/cldf/cldf](https://github.com/cldf/cldf)
- CLDF terms for IGT: `analyzedWord` "The morpheme-pattern analysis of a word in an example" (subproperty of GOLD GrammarUnit, tab-separated multivalued); `gloss` "A gloss corresponding to the morpheme-pattern analysis of a word" (seeAlso GOLD hasGlosses; definition does not cite Leipzig); `primaryText`, `translatedText`, `metaLanguageReference`; `LGR_Conformance` "The level of conformance of the example with the Leipzig Glossing Rules", values WORD_ALIGNED, MORPHEME_ALIGNED; `Example_ID` dc:format GOLD InterlinearGlossedText; `Part_Of_Speech` → GOLD PartOfSpeechProperty — [CLDF terms](https://cldf.clld.org/v1.0/terms.html)
- CLDF TextCorpus module: requires only ExampleTable; optional ContributionTable per text; ordering via `position`; sample columns ID, Primary_Text, Analyzed_Word, Gloss (sample glosses "1SG.SUBJ", "APPL"), Translated_Text, Meta_Language_ID — [TextCorpus README](https://github.com/cldf/cldf/blob/master/modules/TextCorpus/README.md)
- CLDF ParallelText module: "The minimal specification of a Parallel Text Dataset consist of a FormTable"; meanings = parameters, translations = forms; FunctionalEquivalentTable with `Segment_Slice` values like `3`, `4:5`, `2 4:5`; example: Parallel Bible Corpus, Matthew 1:1 = parameter `40001001`, form id `aai_40001001` — [ParallelText README](https://github.com/cldf/cldf/blob/master/modules/ParallelText/README.md)

### Inferences
- GOLD and OLiA can serve as *URIs for concept identity* (e.g. documenting that our `PFV` = gold:PerfectiveAspect) but should not be the data format; their licensing (GOLD none, OLiA data CC BY 3.0) is acceptable for citation, and GOLD's absent licence only matters if its OWL were redistributed.
- CLDF's ExampleTable + LGR_Conformance is the only standard that stores Leipzig glosses machine-readably; its ParallelText module already uses the Parallel Bible Corpus verse-id convention, so a CLDF export of drafts/alignments is straightforward with pycldf.

### Gaps
- Whether OLiA contains an Annotation Model for UD v2 (relations/features) was not verified.
- GOLD maintenance status after 2010 and its licence remain unknown.

## KQ1. Which standard should supply (a) relation names, (b) feature names and values, (c) gloss abbreviations; where do they conflict?

### Takeaway
Only UD defines clause relations, so (a) must be UD (`nsubj`, `obj`, `advcl`, `ccomp`, `xcomp`, `acl:relcl`, `conj`, `parataxis`, `vocative`, `discourse`, `dislocated`, `mark`, `case`) with documented subtypes. For (b) UD feature *names* (`Tense`, `Aspect`, `Voice`, `NounClass`, `Clusivity`, `Evident`, `Polite`, layered `Person[obj]`) with UD values are the interoperable choice; where UD lacks a value (applicative, switch-reference, remote/hodiernal tense, perfective vs perfect) UniMorph labels fill the gap and double as (c) because they are the same strings as the Leipzig abbreviations in most cases. The documented conflicts are: UD `Imp` (imperfect/imperative), UD `Perf` (perfect but used for perfective/aorist), UD `Jus` vs UniMorph `IMP` (imperative-jussive), UD `In/Ex` vs `INCL/EXCL`, UD `Cau` (Voice) vs `CAUS` (Valency), UD `Ind` (indicative or indefinite depending on feature).

### Cited Findings
- UD VerbForm/Tense/Aspect fuse "tense names" with aspect: "In some languages (e.g. English), some tenses are actually combinations of tense and aspect"; `Tense=Imp` "imperfect tense is not always the same as past tense + imperfective aspect" — [UD Tense](https://universaldependencies.org/u/feat/Tense.html)
- McCarthy et al. 2018 on this: mapping `TENSE=IMP` to `IPFV` "crosses semantic categories: IPFV represents the imperfective aspect, whereas TENSE=IMP comes from imperfect … UniMorph chooses to split this into the atoms PST and IPFV, while UD unifies them according to the familiar name of the tense"; attested annotations of Spanish *mandaba*: UD `Mood=Ind|Number=Sing|Person=3|Tense=Imp|VerbForm=Fin`, UniMorph `V;IND;PST;3;SG;IPFV`; "In each schema, order of the values is irrelevant"; "UD separates the part of speech from the remainder of the morphosyntactic description" — [McCarthy et al. 2018 PDF](https://aclanthology.org/W18-6011.pdf)
- UniMorph vs Leipzig label identity (from the two lists above): identical strings for PFV, IPFV, PRF, PROG, HAB, PST, PRS, FUT, IND, SBJV, IMP, IRR, COND, OPT, POT, ACT, PASS, MID, ANTIP, CAUS, APPL, RECP, REFL, INCL, EXCL, SG, PL, DU, DEF, INDF, NEG, FOC, TOP, FIN, PTCP≈V.PTCP, CVB≈V.CVB, NOM, ACC, GEN, DAT, ABL, ALL, LOC(absent in UniMorph: UniMorph uses IN/ON/AT), INS, ERG, ABS, VOC, BEN, COM, PROX, DIST (UniMorph REMT/REM), QUOT — [unimorph-schema.pdf](https://unimorph.github.io/doc/unimorph-schema.pdf); [Leipzig PDF](https://www.eva.mpg.de/lingua/pdf/Glossing-Rules.pdf)
- UD values vs the same categories: `Clusivity=In/Ex` (UniMorph/Leipzig INCL/EXCL); `Voice=Cau` (UniMorph Valency CAUS; Leipzig CAUS); `Mood=Jus` (UniMorph IMP "Imperative-Jussive"; Leipzig has no JUS, has PROH); `Mood=Qot` quotative (UniMorph Evidentiality QUOT; Leipzig QUOT); `Evident=Fh/Nfh` (UniMorph FH/NFH + 9 more); `Polite=Infm/Form/Elev/Humb` (UniMorph INFM/FORM/ELEV/HUMB + 9 more; Leipzig none); `Definite=Cons` construct state (UniMorph and Leipzig none); `Aspect=Perf` glossed "perfect" (UniMorph separates PFV/PRF; Leipzig PFV/PRF); `Aspect=Imp` glossed "imperfect" (UniMorph/Leipzig IPFV) — [UD u/feat/all](https://universaldependencies.org/u/feat/all.html); [UD Aspect](https://universaldependencies.org/u/feat/Aspect.html); [UD Mood](https://universaldependencies.org/u/feat/Mood.html)
- UD says value codes are not globally unique: "Sup could denote the superessive case, superlative degree of comparison or supine" — [UD morphology overview](https://universaldependencies.org/u/overview/morphology.html)
- Applicative: not a UD universal Voice value ("The page does not mention applicatives") — [UD Voice](https://universaldependencies.org/u/feat/Voice.html); Ruuli-RDT and Wolof-WTB use language-specific `Voice=Appl` / relations `obj:appl`, `iobj:appl`, `obl:appl`, `obj:caus` — [ruc_rdt](https://universaldependencies.org/treebanks/ruc_rdt/index.html); [wo_wtb](https://universaldependencies.org/treebanks/wo_wtb/index.html)
- UniMorph POS vs UD UPOS: UniMorph has 19 POS labels incl. V.PTCP, V.CVB, V.MSDR, ART, COMP, CLF, PRO; UD has 17 UPOS and puts participle/converb/verbal noun under `VerbForm=Part/Conv/Vnoun` — [unimorph-schema.pdf](https://unimorph.github.io/doc/unimorph-schema.pdf); [UD VerbForm](https://universaldependencies.org/u/feat/VerbForm.html)
- McCarthy et al. also note UniMorph data "only exist for nouns, verbs, and adjectives", UniMorph lacks lexical features that UD has (PronType etc. are "fixed lexical features" in UD), and that irremediable discrepancies arise "when one resource marks gender and the other marks case"; conversion recall macro-average 64.13% — [McCarthy et al. 2018](https://aclanthology.org/W18-6011/)

### Inferences
- Recommended split: relation names = UD (incl. documented subtypes such as `advcl:cond`, `advcl:purp`, `obl:tmod`, `compound:svc`, `obj:appl`); feature *names* = UD (so files validate as CoNLL-U and UD tooling works); feature *values* = UD codes where they exist, with a published, one-to-one mapping table to UniMorph/Leipzig labels, and UniMorph labels (as UD-style capitalised codes, e.g. `Voice=Appl`, `SwitchRef=Ds`, `Tense=Hod`) for categories UD lacks. The gloss layer for agents and humans = Leipzig abbreviations, which are the UniMorph labels.
- The real semantic conflicts to decide once in the project: (1) `Perf` vs PFV/PRF (Hebrew qatal and Greek aorist are "perfective"; Greek perfect is "perfect"; UD treebanks conflate them — see KQ2); (2) `Imp` ambiguity (UD Tense=Imp imperfect, Mood=Imp imperative; Leipzig IMP imperative, IPFV imperfective); (3) Jussive (UD `Jus`, UniMorph folds it into IMP); (4) Ind = indicative (Mood) / indefinite (PronType, Definite) in UD vs IND/INDF in Leipzig.

### Gaps
- No standard defines speech-act or discourse-relation labels (declarative/interrogative/imperative is only partly covered: UniMorph Interrogativity DECL/INT, UD Mood=Int as a verb form, Leipzig DECL/Q); the specification's "speech act" and "discourse" slots have no accepted vocabulary to inherit.

## KQ2. How Biblical Hebrew and Koine Greek are already represented in UD

### Takeaway
UD_Ancient_Hebrew-PTNK (ETCBC BHSA-derived, CC BY-NC 4.0, 5,608 sentences / 145,866 words in v2.18) encodes binyan as `HebBinyan` (7 values), qatal as `Aspect=Perf`, yiqtol as `Aspect=Imp`, wayyiqtol as `Tense=Past` with no Aspect (the ו split off as its own token), imperatives `Mood=Imp`, infinitives `VerbForm=Inf`, participles `VerbForm=Part`; construct chains are `compound:smixut`, not `Definite=Cons`; לֵאמֹר is `SCONJ`/`mark` on the quotation and quotations are `ccomp`. UD_Ancient_Greek-PROIEL (NT + Herodotus, CC BY-NC-SA 3.0) maps aorist *and* perfect alike to `Tense=Past|Aspect=Perf`, imperfect to `Tense=Past|Aspect=Imp`, pluperfect `Tense=Pqp`, future perfect `Tense=Fut|Aspect=Perf`, voices Act/Mid/Pass/Mid,Pass, moods Ind/Sub/Imp/Opt, `VerbForm=Fin/Inf/Part/Gdv`.

### Inferences
- In PTNK the three Hebrew finite conjugations are told apart by *which* feature is set (Tense=Past alone = wayyiqtol; Aspect=Perf = qatal; Aspect=Imp = yiqtol); weqatal is not distinguishable in FEATS from qatal (the ו is a separate token), and jussive/cohortative are not marked (Mood has only Ind/Imp). For our clause specification a dedicated conjugation value (e.g. `VerbType`/`Conj=Wayq|Weqt|Qtl|Yqtl|Impv|Juss|Coh|Inf|InfAbs|Ptc`) is clearer than this encoding and can be mapped to UD FEATS.
- In PROIEL's UD files the aorist/perfect contrast is lost in FEATS (both `Tense=Past|Aspect=Perf`); any pipeline that needs it must read the original PROIEL morphology tag (XPOS) or MACULA Greek, and our specification should keep aorist (PFV) and perfect (PRF) distinct, as UniMorph/Leipzig do.
- UD's accepted analysis of Hebrew quotation (לֵאמֹר = `mark`, quote = `ccomp` of the speech verb) and of construct chains (`compound:smixut`, head = construct noun) are precedents the specification can cite rather than invent.

### Gaps
- Whether grc_proiel keeps the PROIEL tag in XPOS (so the aorist/perfect distinction survives in the file) was not verified from the files.
- The hbo docs do not state the wayyiqtol→`Tense=Past` rule explicitly; it is inferred from the statistics page's example forms.

## KQ3. What is missing in UD/UniMorph for Bantu and Papuan phenomena, and how have treebanks for such languages handled noun class, concord, applicatives, tone?

### Takeaway
There is no Papuan UD treebank at all and no UniMorph Papuan language; for Bantu, UD has one real treebank (Ruuli-RDT, Uganda, 6k words, CC BY-NC-SA 4.0, v2.18) plus a 20-sentence Tswana pilot and an empty Swahili repository. Ruuli shows the workable UD pattern: one token per verb, `NounClass`/`Person`/`Number` with layers `[obj]`, `[iobj]`, `[psor]`, `[psed]`, `Voice=Appl|Cau|Pass|Rcp|Rfl` (+ `Voice[add]` for a second extension), `Tense=Nar` and relations `obj:appl`, `iobj:appl`, `obj:caus`. Tone is not encoded in any treebank or standard; switch-reference and serial verbs have only UniMorph labels (SS/DS) and the UD relation `compound:svc`.

### Cited Findings

### Inferences
- For a Bantu target (Zinza) the Ruuli-RDT scheme is the closest published precedent and is fully UD-conformant: verb = one token with `Person`/`Number`/`NounClass` (subject), `…[obj]`, `Voice=Appl/Cau/Pass`, `Voice[add]` for stacked extensions, `Tense=Nar` for narrative tense, `Polarity=Neg`; the Tswana pilot shows the alternative (concords as PRON tokens with `expl`/`nsubj`) that disjunctive orthographies force and that the authors themselves call unsolved.
- For a Papuan SOV target (Kuni) there is no treebank precedent; Yupik-SLI (layered Person[subj]/[obj], language-specific Mood values, morpheme-level tokens) is the nearest UD model for polysynthetic prefix/suffix chains, and UniMorph's SS/DS labels are the only standard switch-reference vocabulary.
- Tone as a grammatical marker must be project-defined: either as a feature on the word (e.g. `Tone=H`/`ToneMelody=…`) or, in glosses, with Leipzig `\` (e.g. `NEG\PST`); no standard offers a value set.

### Gaps
- No source describes a UD treatment of a Papuan language; claims about fit for Kuni are inference.
- Ruuli tokenisation rule (whole verb vs split) is inferred from the example forms on the statistics page, not stated.

## KQ4. How compact are the encodings (UD FEATS vs UniMorph vs Leipzig), and which is best for token economy and Python parsing?

### Takeaway
Measured by characters on the same content, UD FEATS is roughly 3× UniMorph flat and 4× Leipzig (31 vs 10 vs 7 characters for 1SG past; 107 vs ~47 vs ~24 for a Bantu verb with class concords and an applicative). UD is the easiest to parse (`dict(f.split('=') for f in s.split('|'))`) and self-documenting (feature names carried); UniMorph flat is a set (`s.split(';')`) whose labels must be looked up to know the dimension; Leipzig is a morpheme-aligned string that needs a real parser (pyigt) and encodes morpheme order, which UD/UniMorph do not.

### Cited Findings
- UD FEATS syntax: `Name=Value` pairs joined by `|`, sorted, multi-values by `,`; names `[A-Z][A-Za-z0-9]*(\[[a-z0-9]+\])?`, values `[A-Z0-9][A-Za-z0-9]*` — [UD format](https://universaldependencies.org/format.html)
- UniMorph syntax: `;`-separated, unordered, labels only; `+`, `{/}`, `non{}` for complex values; 4.0 adds `NOM(3,SG)`-style nesting — [unimorph-schema.pdf](https://unimorph.github.io/doc/unimorph-schema.pdf); [UniMorph 4.0](https://aclanthology.org/2022.lrec-1.89/)
- Leipzig syntax: hyphen-separated morphemes, `.` inside a morpheme gloss, person+number unseparated (`1PL`), optional `:`/`;`/`_`/`\`/`>`/`~`/`< >` — [Leipzig PDF](https://www.eva.mpg.de/lingua/pdf/Glossing-Rules.pdf)
- Example equivalents attested side by side: UD `Mood=Ind|Number=Sing|Person=3|Tense=Imp|VerbForm=Fin` ↔ UniMorph `V;IND;PST;3;SG;IPFV` (Spanish *mandaba*) — [McCarthy et al. 2018 PDF](https://aclanthology.org/W18-6011.pdf); UD `Mood=Ind|Number=Sing|…` ↔ `PRS;V;FIN;3;IND;SG` — [ud-compatibility README](https://github.com/unimorph/ud-compatibility)
- pyigt parses LGR glosses into Morpheme/GlossElement objects (`GlossElementAfterColon`), reports `igt.conformance` (`LGRConformance.MORPHEME_ALIGNED`) and raises "Rule 2 violated: Number of morphemes does not match number of morpheme glosses!" — [cldf/pyigt](https://github.com/cldf/pyigt)
- Character counts (computed here on constructed examples; no tokenizer was run, token figures are my estimates of typical BPE behaviour and should be re-measured with the project's tokenizer):
  - "1st person singular, past": UD `Person=1|Number=Sing|Tense=Past` = 31 chars (≈12 tokens); UniMorph `V;1;SG;PST` = 10 chars (≈7–8 tokens); Leipzig `1SG.PST` = 7 chars (≈4–5 tokens).
  - "3sg class-1 subject, class-7 object, negative, past, applicative, finite verb": UD `NounClass=Bantu1|NounClass[obj]=Bantu7|Number=Sing|Person=3|Polarity=Neg|Tense=Past|VerbForm=Fin|Voice=Appl` = 107 chars; UniMorph 4.0 `V;FIN;PST;NEG;APPL;NOM(3,SG,BANTU1);ACC(BANTU7)` = 47 chars; Leipzig bundle `NEG.SM1.PST.OM7.APPL` (SM/OM are common Bantuist extensions, not in the Leipzig list) = 20 chars, or as morpheme gloss `NEG-SM1-PST-OM7-eat-APPL-FV` = 27 chars.

### Inferences
- For LLM agents the Leipzig/UniMorph label style is 3–4× cheaper than UD FEATS, and the labels are the ones linguists (and the models) already know; for scripts UD's explicit `Name=Value` costs nothing and prevents the `Imp`/`Ind`/`Sup` ambiguities. A sensible design is one canonical internal representation (dict of UD-named features) with two serialisations: CoNLL-U FEATS for files/tooling and a Leipzig-style bundle (`3SG.C1>C7.NEG.PST.APPL`) for prompts; the mapping is a static table.
- Leipzig alone is unsuitable as the *only* storage format: it is positional (needs the segmented form beside it) and its optional variants (`:` `;` `_`) make round-tripping lossy unless the project fixes one variant.

### Gaps
- Token counts were not measured with a real tokenizer; a sibling note in this folder (`encoding_token_measure.py`, written by another researcher) may supply measured figures.

## KQ6. Python tooling and interoperability (UD↔UniMorph, CoNLL-U Plus, CLDF/IGT)

### Takeaway
Mature, permissively licensed readers exist for UD (conllu 6.0.0 MIT; pyconll 4.1.1 MIT; udapi 0.5.2 GPL-3.0) and CLDF (pycldf 2.1.1 Apache-2.0); Leipzig IGT handling is pyigt 2.3.0 (GPL-3.0); the UD→UniMorph converter (`marry.py`, GPL-3.0) is deterministic and reports 64% recall on real treebanks because the two schemes annotate different attributes. CoNLL-U Plus is the sanctioned way to add project columns (e.g. a UniMorph or Leipzig column, or clause-level columns) next to UD columns.

### Cited Findings
- PyPI (queried 2026-10-22): conllu 6.0.0, "The MIT License (MIT) Copyright (c) 2016 Emil Stenström"; pyconll 4.1.1 (GitHub licence MIT); udapi 0.5.2 (GitHub licence GPL-3.0); unimorph 0.0.4 (no licence field; GitHub repo `unimorph/unimorph` licence None); pycldf 2.1.1 Apache 2.0; pyigt 2.3.0 GPL — [PyPI conllu](https://pypi.org/project/conllu/); [pyconll](https://github.com/pyconll/pyconll); [udapi-python](https://github.com/udapi/udapi-python); [unimorph](https://github.com/unimorph/unimorph); [pycldf](https://github.com/cldf/pycldf); [pyigt](https://github.com/cldf/pyigt)
- conllu: "A CoNLL-U parser that takes a CoNLL-U formatted string and turns it into a nested python dictionary" — [github.com/EmilStenstrom/conllu](https://github.com/EmilStenstrom/conllu); pyconll: "A minimal, pure Python library to interface with CoNLL-U format files" — [pyconll](https://github.com/pyconll/pyconll); udapi: "Python framework for processing Universal Dependencies data" — [udapi-python](https://github.com/udapi/udapi-python)
- ud-compatibility (`marry.py`): "converts Universal Dependencies (UD) v2 corpora into the UniMorph schema using a deterministic feature mapping"; usage `python marry.py convert --ud <file> [-l <lang>]`, `--langs he ro de …`, `evaluate`, `replicate`; Python 3.5+, `termcolor`; extension by a `Translator` subclass registered in `languages.py`; licence GPL-3.0 — [ud-compatibility](https://github.com/unimorph/ud-compatibility)
- McCarthy et al. 2018: "a deterministic mapping from Universal Dependencies v2 features into the UniMorph schema", "macro-average recall of 64.13%", incompatibilities "due to paucity of data on either side"; conservative rule: "we do not add new values that cannot be unequivocally inferred from the existing data"; language-specific failures: Basque argument encoding, Irish (UD marks gender, UniMorph case), Dutch (UD "impoverished"), Arabic/Hindi/Lithuanian/Persian/Russian low overlap; UniMorph records only for N, V, ADJ — [McCarthy et al. 2018](https://aclanthology.org/W18-6011/) (PDF text)

- pyigt: reads IGT "stored as CLDF examples", `Corpus.from_path()`, `igt ls` CLI, abbreviation expansion, `LGRConformance` levels — [pyigt](https://github.com/cldf/pyigt); CLDF `LGR_Conformance` values WORD_ALIGNED / MORPHEME_ALIGNED — [CLDF terms](https://cldf.clld.org/v1.0/terms.html)

### Inferences
- For the toolkit (Python, PyYAML): `conllu` (MIT) is sufficient for CoNLL-U/CoNLL-U Plus I/O; a 20-line mapping table (UD value ↔ UniMorph/Leipzig label) replaces `marry.py` (GPL) for our fixed feature set; `pycldf` (Apache) is the natural exporter if drafts and glossed examples are to be published as a CLDF TextCorpus/ParallelText dataset.
- The MISC `MSeg`/`MGloss` convention plus a CoNLL-U Plus column is a standards-conformant home for the Leipzig gloss of a target-language draft next to the UD analysis of the source clause.

### Gaps
